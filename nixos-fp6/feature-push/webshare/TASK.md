# Task: "Share via link/QR" for iPhones and any device (Rust)
Because AirDrop is not possible on this hardware, build a universal local-network share: the phone starts a temporary HTTPS (self-signed, with the certificate fingerprint shown) or HTTP-on-LAN web server and shows a QR code + short URL; any phone or computer on the same network (iPhone, Android, laptop) opens it in a browser to (a) download the files the user shared, (b) upload files to the phone (optional, off by default, each upload needs confirmation on the phone), (c) send text/links to the phone clipboard (opt-in). Security: random one-time token in the URL, server stops automatically after the transfer or N minutes, binds only to Wi-Fi/hotspot interfaces, rate limits, upload size limits, never overwrite, path traversal rejection, no directory listing beyond the shared items. Works also over the phone hotspot (so it works without a shared Wi-Fi). Lomiri app + content-hub share target ("Share via link"), D-Bus API com.fairphone6.WebShare1, CLI fp6-webshare. The web page itself must be mobile-friendly, no external resources, works in Safari.
Context: target is the Fairphone 6 running aarch64 NixOS (Mobile NixOS) with the Lomiri shell (Ubuntu Touch UI): Qt 5.15 + Lomiri UI Toolkit 1.3 (Suru look) QML apps, systemd *user* services, D-Bus IPC, PipeWire audio, Maliit on-screen keyboard. New code in Rust (stable, no unsafe unless justified). UITK 1.3 notes: Label has no topPadding/bottomPadding (use margins); GSettings keys must not use ai/ax types. Deliver in this git repo, committing in small steps: the Rust crate(s), QML UI (must render offscreen with QT_QPA_PLATFORM=offscreen for previews; save preview PNGs under previews/), a Nix `package.nix` (rustPlatform.buildRustPackage) and `module.nix` (NixOS module with an enable option under hardware.fairphone6.*, user service, desktop file with X-Lomiri-Touch=true), tests (cargo test must pass on this x86_64 laptop; export NIX_PATH=nixpkgs=channel:nixos-unstable for nix-build checks), DESIGN.md and README.md (incl. a manual test checklist for the real phone), and finish with FINAL_REPORT.md. No telemetry, privacy by default, synthetic data only in tests, do not access any phone or remote host beyond fetching sources/crates.
