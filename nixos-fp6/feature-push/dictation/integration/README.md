# Maliit and Lomiri integration

This repository supplies a working service and a **patch sketch**, not a compiled replacement keyboard/shell. The sketch targets the structure of upstream [maliit/keyboard](https://github.com/maliit/keyboard/tree/cbb0bbfa67354df76c25dbc3b1ea99a376fd15bb) inspected on 2026-10-27. Adapt paths and input-context notifications to the Lomiri fork being shipped.

1. Link the existing keyboard plugin to Qt5::DBus. Add a DictationBridge QObject to `src/plugin`, expose it as `dictation` before `d->view->setSource()` in `InputMethod` construction. Keep **one** QDBusConnection for Start/Stop/Cancel, since reconnecting changes the owner identity. All calls use QDBusPendingCallWatcher and a 100,000 ms timeout; never block the GUI thread.
2. Add a microphone key beside the space/language key. Support hold/release, or an explicit toggle preference for accessibility; do not implement both gestures using the same press event without distinguishing them. While transcription runs, show a spinner and allow Cancel. Surface missing-model/Busy/capture errors in a small nonmodal message. Use an accessible name and the active recording color.
3. On Start, record the input-context generation. On release before Start replies, remember `stopWhenStarted`; when its ID arrives, issue Stop immediately. On focus loss, client change, keyboard hide, lock, password/PIN/hidden-text hints or user Cancel, increment the generation and cancel any session. If Start completes after invalidation, cancel its returned ID. Reject results after generation mismatch. A maximum-duration idle signal resets the button.
4. Stop returns final text. Only for the unchanged, still-focused, non-sensitive input context, clear/finish preedit according to the editor's existing policy and call the input method host's `sendCommitString(text)`. Do not simulate key events or use the clipboard. Empty text commits nothing. Ensure the word engine does not autocorrect the dictation a second time. The sketch shows `d->editor.commitPreedit()` followed by `d->host->sendCommitString(text)`; review spacing and prediction reset in the selected fork.
5. Attach `reset()`, `handleClientChange()`, `handleFocusChange(false)`, hide and shell lock paths to invalidation. Never move a finished transcript into the next field. Password/privacy controls must be checked both before Start and immediately before commit.

## Privacy indicator hook

The service's `StatusChanged(state, mic_active)` and `MicActive` property provide a ready hook. Add a shell-side adapter that subscribes **before** reading the initial property and uses `QDBusServiceWatcher` to clear state when the service disappears. It should re-read the property on name acquisition, and marshal updates onto the GUI thread. The included QML indicator component consumes the adapter's boolean.

For the authoritative system-wide indicator, use the existing shell/WirePlumber PipeWire registry monitor. Count linked/running capture nodes with `media.class=Stream/Input/Audio`, including `application.name=FP6-Dictation`, `node.name=fp6-dictation`, `media.role=Communication`. Never key the global microphone icon only on the dictation daemon: other apps may still be recording. The daemon property is conservative (process launched, potentially still connecting), so OR it with observed dictation capture activity; graph node removal resolves crash/teardown delays. `transcribing` does not keep the microphone icon lit after capture is closed. The icon should be shell-owned and visible even when the keyboard hides.

On hardware, verify the icon with `pw-dump`/the graph monitor, route changes, Cancel, daemon kill, client crash, and a second unrelated microphone app. `pw-dump` is a manual diagnostic, not a recorder. No shell is modified by the Nix module; integrate this hook in the phone's Lomiri build before treating the indicator acceptance criterion as complete.
