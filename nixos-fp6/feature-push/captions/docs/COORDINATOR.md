# Lomiri coordinator handoff

The module installs an app and user service. It does not patch Lomiri, telephony, WirePlumber or indicator packages. These integration items are necessary before shipping on the phone.

1. **Privacy activity:** observe `com.fairphone6.Captions1` at `/com/fairphone6/Captions1`, signal `Updated(s)` and method `Snapshot()`. When `capture_active` is true, add a live audio-capture claim keyed by service unique bus owner and source. For microphone mode, join the existing microphone-in-use indicator; for device audio, show an equally visible "device audio in use" claim using the existing privacy activity semantics. Label the app Live Captions. Combine claims across dictation, calls and other recording apps; never clear another app's indicator when captions stops. Retain activity until the corresponding PipeWire node disappears. Observe `NameOwnerChanged` to clear stale service claims, then reconcile actual nodes. Stream names are listed in DESIGN.md. The in-window green dot is additional feedback, not a replacement for the global indicator.

2. **Call privacy:** call routing must atomically block monitor links to call playback unless the caption session explicitly opted in (`allow_calls` in Snapshot). Stop captions before dialing/answering/routing a call, including VoIP and all SIMs, and keep them disabled while ringing/held/active. Handle telephony daemon loss as unknown and deny capture. The application's oFono polling is defense in depth, not an atomic routing barrier. Require a new user Start after calls end. Propagate a reliable pre-route signal or add a WirePlumber policy that excludes call nodes; a sink monitor inherently mixes routed audio, so excluding individual streams may require a separate non-call virtual sink. Do not claim absolute call exclusion from the app alone.

3. **Quick-settings tile:** label Live Captions, use an accessibility/subtitles icon, open the UI on long press. On explicit activation the shell may call Start with the user's chosen options and **hold that D-Bus connection** as controller, or launch the UI for the user to start. Deactivation calls Stop and waits for inactive status. Pending state follows `starting`; checked state follows `capture_active`. Display a readable failure for missing models or unknown call status. Never set `allow_calls=true` implicitly. Listen for service disappearance, clear stale text/activity and return the tile to off. Keep downloads an explicit action; no network from the tile/service.

4. **Shell overlay:** use a compositor-authorized always-on-top surface that does not take focus from the playing app or Maliit. Reuse the caption panel styling, but supply shell-managed position/safe insets, touch drag/collapse, scaling, accessibility, keyboard avoidance and orientation handling. Decide whether to show only the last two/three lines; retain the bounded text policy. Prevent the overlay appearing on the lock screen. Stop capture on session lock, suspend and logout. A suspended app controller must not leave unacknowledged capture running; the shell should own such a session only while it can supervise it.

5. **Acceptance:** execute the README checklist on the actual aarch64 build, record latency/accuracy/thermal/battery findings, and verify that node activity and call-route exclusions hold during crashes, routing changes and daemon restarts. Do not mark the call/privacy/tile integration complete based only on the offscreen preview.
