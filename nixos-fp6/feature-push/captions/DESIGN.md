# Streaming captions design

## Reuse and boundaries

`models.json`, verified download structure and decoder setup are adapted from the read-only sibling fp6-dictation working tree, with source hashes recorded in FINAL_REPORT.md, under its retained MIT license. Only the multilingual tiny/base Q5 catalog entries are copied. No path dependency, D-Bus call to Dictation1, sibling write or model bundle is required. The existing Dictation1 API remains untouched. Captions owns `com.fairphone6.Captions1` at `/com/fairphone6/Captions1` on the user bus.

`streaming.rs` is a model-independent candidate for upstreaming: feed exact 20 ms, mono 16 kHz f32 frames, receive bounded `Chunk`s with sample positions and overlap metadata, then feed decoded text to `Merger`. `engine.rs` adapts the single-shot dictation engine to retain a whisper state across windows. Its CPU-only greedy decoder sets English or Romanian explicitly, disables translation/context/realtime printing, and accepts at most two seconds. It caps each window at 64 tokens and uses the upstream experimental 256-position (5.12 s) audio context override to avoid encoding 30 seconds of padding per short window; this is an explicit accuracy/performance tradeoff that needs phone evaluation. Native logging hooks are disabled even in debug builds to prevent transcript-bearing diagnostics. Automatic language detection is intentionally omitted. Q5 is supported; an int8 model would require a new independently verified catalog entry and performance evaluation.

## Audio and latency

A `pw-record` child emits raw mono PCM16 at 16 kHz through a pipe. Device audio sets `stream.capture.sink=true` and leaves the target automatic, allowing WirePlumber to choose the default sink monitor. `node.dont-fallback=true` prevents fallback to another target when routing fails. Microphone mode is a distinct explicit selection. PipeWire performs channel conversion/resampling. Stream metadata identifies `FP6-Captions`, `fp6-captions`, `Live-Captions` and the Accessibility role. Neither mode is opened until model verification/loading and call checks succeed.

The energy VAD threshold is RMS 0.01 on each 20 ms frame. It retains 100 ms pre-roll, requires 100 ms fresh voiced samples, emits after 300 ms quiet or 1.5 s total, and retains 400 ms overlap for continuous speech. Subsequent full windows advance about 1.1 s. The first estimate arrives after up to 1.5 s accumulation + inference + PipeWire (~40 ms requested) + UI polling (up to 200 ms); short utterances can end sooner. This is a latency budget, not a validated 1–2 s guarantee.

Energy gating is deliberately simple: music, game sounds and noise may be mistaken for speech, and very quiet speech may be rejected. Whisper can hallucinate on non-speech. Caption text is provisional, and there is no word-level timestamp reconciliation. The merger matches up to 16 normalized Unicode words between an old suffix and new prefix only for overlapping windows. It handles punctuation/case differences but cannot repair altered words, partial words or translation-like hallucinations. Even a one-word match can remove an intended repeated word. Silence/new utterances disable overlap matching.

Capture and decode are independent async loops. A watch channel retains only the latest pending chunk while a child worker decodes one chunk. Gaps increment a counter and reset text continuity; there is no unbounded audio backlog. PCM is bounded by current segmentation, one pending chunk, one worker request, and OS pipes. Worker replies are bounded by the trusted decoder's maximum input/output behavior; corrupt protocol replies fail the session. A 15 s decode timeout and 5 s capture-stall timeout stop the session. The worker is a separate process so cancellation can kill native inference immediately. Model load has a 60 s timeout. No unsafe code is handwritten: the library and CLI forbid unsafe Rust; the UI uses qmetaobject's generated Qt/C++ ABI glue, which necessarily contains upstream unsafe FFI. QObjectBox pins the bridge for the engine lifetime, and cross-thread UI state uses synchronized Rust memory instead of Qt object access.

## Lifecycle and privacy

States are idle, starting, listening and idle with a message on stop/error. One controller owns a session through its unique D-Bus connection. Start rejects a second session; Stop is intentionally available to any same-user controller. Owner disappearance is checked every 100 ms, including model startup. Start acknowledges scheduling, not capture success; the client must observe Snapshot/Updated. The UI continuously polls a cached snapshot while a background Rust thread handles D-Bus, so model startup never blocks the Qt thread. The CLI holds its bus connection until Ctrl-C or the session stops.

Stop, silence timeout, source EOF, PipeWire stall, decoder error/timeout, owner loss and call gating cancel the session. Children have kill-on-drop and systemd uses control-group cleanup. Audio and text buffers are released, never serialized. Memory is not cryptographically zeroized; freed allocator pages and swap are outside this guarantee. Service core dumps are disabled. Persistent UI preferences contain no text. The only transcript write is the user's explicit Save action: bounded current text, a unique filename, create-new semantics, mode 0600, in a mode-0700 directory. There is no complete-session transcript archive.

Eight seconds of silence clears the displayed text. N minutes of no energy above threshold stops the recorder and worker. Continuous noise can prevent this timer. Capture activity is conservative from recorder spawn until child teardown; the global shell should combine D-Bus state with actual PipeWire node lifetime, as described in the coordinator contract.

Session-bus APIs are not a sandbox boundary against other programs running as the same Unix user. Snapshot and Updated contain current text. The systemd service cannot create Internet sockets (`AF_UNIX` only); downloading is a separate explicit CLI command. Download uses HTTPS-only redirects, size/SHA checks and an atomic rename after verification. A failed file is removed; a previously valid model remains intact. Every session rehashes the selected file before opening audio. Catalog integrity is the trust root. Same-user modification between verification and native load remains outside the same-user threat boundary.

## Calls and shell integration boundary

By default, oFono `GetModems` must return at least one modem and `VoiceCallManager.GetCalls` must succeed with an empty list on every modem. Any call state (including ringing/held), missing interface, no modem, unknown bus or timeout fails closed. A CallAdded subscription is installed before checking calls and stops capture as soon as a signal is received. The call list is also checked before model load, immediately before capture and every 250 ms during capture (each query bounded by 2 s). A call does not automatically resume captions afterward. Explicit `allow_calls=true` bypasses these checks for that session; the UI toggle starts false on every app launch.

Polling cannot atomically exclude samples at the instant a call is routed. The app alone may see a call transition up to 2.25 seconds late if call signals are unavailable and the telephony service stalls. Strict "never capture call audio" requires the coordinator to exclude call playback routes from monitor capture or revoke links before activating a call, and trigger Stop before call setup; see docs/COORDINATOR.md. This is a required production integration item, not a claim that a desktop prototype enforces call routing. VoIP apps outside oFono need the same coordinator signal/routing policy. Until that exists, treat this as a prototype and keep call opt-in off. Do not replace unknown call state with "no calls".

A normal top-level Qt window uses `WindowStaysOnTopHint`, custom drag handling, collapse and opacity. Mobile Lomiri may constrain position/stacking, so a production shell overlay needs a privileged compositor surface, safe-area/keyboard/inset layout, focus policy, shell-managed gestures, lock/suspend behavior and accessibility testing. UITK Label layout uses margins rather than unsupported padding properties. Qt Settings holds scalar string/bool/int/real preferences; no GSettings `ai`/`ax` types are introduced.

## D-Bus contract

The installed XML describes `Start(s options_json)`, `Stop()`, `Snapshot() -> s`, and `Updated(s snapshot_json)`. JSON is version-1 local protocol; reject unknown option keys. Example options:

```json
{"language":"ro","model":"tiny-q5_1","source":"monitor","threads":2,"silence_minutes":3,"allow_calls":false}
```

Snapshot keys: `state`, `capture_active`, `allow_calls`, `source`, `text`, `message`, `dropped`, `decode_ms`. Consumers must clear all text/activity when the bus name disappears and must treat `capture_active`, rather than a successful Start reply, as the activity flag. Same-user clients may read the rolling text. A controller must retain its connection; a one-shot `gdbus call Start` immediately loses ownership. Snapshot polling is a recovery path for a lost Updated signal. UI commands use a bounded four-entry queue and all blocking IPC happens off the Qt thread.

## Resource and validation limits

Default Tiny Q5, two threads, CPUQuota=200%, Nice=5, 600 MiB service cgroup limit and 64 tasks. Models are loaded only for enabled sessions and unloaded on stop. Changing model/language/source/threads requires a new session. Base improves some speech at increased CPU/RAM cost; very short windows trade context/accuracy for responsiveness. Quantized disk size is not peak RAM. Thermal throttling, actual battery cost, recognition quality and absolute latency must be measured on FP6. The synthetic benchmark separates model load, window availability and decoder time. Its serial scheduling simulation does not pretend to be live end-to-end performance; no recorded human data is used.
