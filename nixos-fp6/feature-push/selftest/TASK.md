# Task: fp6-selftest — post-update health and feature smoke tests (Rust)
A read-only (by default) self-test runner for the phone, run after every OTA update (systemd user + system units, also manual via CLI and a Settings "Run self-test" page) that checks the health of the base system and every Fairphone-6 feature service, and prints a clear PASS/WARN/FAIL report (also JSON) saved under ~/Documents/Self-tests/ (0600).
Checks (each a small plugin with a timeout; skip with SKIP when the feature is not installed):
- base: /etc/fp6-release readable, failed systemd units (system + user), coredumps since boot, journal errors per unit, disk space, memory/zram, display-manager + lomiri.service active, maliit running, PipeWire/WirePlumber default sink/source exist, NetworkManager state, Bluetooth adapter present, modem: oFono modem online/powered + SIM present + registration (no identifiers printed), mobile data context active if enabled, GPS service presence, fingerprint daemon reachable.
- feature D-Bus services: for each of com.fairphone6.QuickShare1, WebShare1, KdeConnect1, Ocr1, Dictation1, Share1, UsbModes1, Update1 (OTA), Calls1 (if installed), the notifications/DND daemon, battery daemon, app-ready, privacy daemon, gestures, netpolicy helper: check the name is activatable/owned, introspect, call a harmless read-only method/property (status/version), and validate the reply shape. Discover the real interfaces from the sibling directories (../quick-share, ../webshare, ../kdeconnect, ../ocr, ../dictation, ../sharesheet, ../netpolicy, ../bugreport, ../callkit — read-only) and otherwise make the check list data-driven (a TOML file listing bus name, object path, interface, read-only probe) so the coordinator can extend it for in-tree services.
- settings schemas: every com.fairphone6.* GSettings schema compiles and contains no ai/ax keys (that type crashes gsettings-qt).
- desktop entries: every X-Lomiri-Touch desktop file has an existing Exec and Icon.
Never change state, never play audio, never send network traffic beyond local D-Bus, never print personal identifiers (reuse a redaction step for anything echoed). Exit code reflects worst result. Include an OTA hook design: the update health-check (fp6-updated start check) could call `fp6-selftest --quick --json`. Tests: unit tests with mocked D-Bus (private bus) and fixture schemas/desktop files.
Context: target is the Fairphone 6 running aarch64 NixOS (Mobile NixOS) with the Lomiri shell (Ubuntu Touch UI): Qt 5.15 + Lomiri UI Toolkit 1.3 (Suru look) QML apps, systemd *user* services, D-Bus IPC, PipeWire audio, Maliit on-screen keyboard. New code in Rust (stable, no unsafe unless justified). UITK 1.3 notes: Label has no topPadding/bottomPadding (use margins); GSettings keys must not use ai/ax types. Deliver in this git repo, committing in small steps: the Rust crate(s), QML UI (must render offscreen with QT_QPA_PLATFORM=offscreen for previews; save preview PNGs under previews/), a Nix `package.nix` (rustPlatform.buildRustPackage) and `module.nix` (NixOS module with an enable option under hardware.fairphone6.*, user service, desktop file with X-Lomiri-Touch=true), tests (cargo test must pass on this x86_64 laptop; export NIX_PATH=nixpkgs=channel:nixos-unstable for nix-build checks), DESIGN.md and README.md (incl. a manual test checklist for the real phone), and finish with FINAL_REPORT.md. No telemetry, privacy by default, synthetic data only in tests, do not access any phone or remote host beyond fetching sources/crates.
